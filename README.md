# Pavlodar — KMG Security Agent

Общий репозиторий команды: учебная система обращений KMG и консольный ИИ-анализатор ее информационной безопасности.

```text
pavlodar/
├── KMG-Digital-Hackathon/     # приложение, которое проверяем
├── kmg-security-agent/       # наш анализатор, инструкции и тесты
└── .github/workflows/        # общие автоматические проверки
```

Агент читает исходники и документацию, проверяет восемь требований ИБ детерминированными правилами и LLM (OpenAI-совместимый API) и возвращает результат для CI. Он не запускает код проверяемого приложения и не исправляет его автоматически.

## Начать работу

Клонируйте **весь этот репозиторий** обычным `git clone`, затем перейдите в папку агента. Submodules и отдельное клонирование двух проектов не нужны.

Нужен Python 3.11 или новее; CI использует 3.14. Для самого агента сторонние зависимости не нужны. Поддерживаются Windows, Linux и macOS; инструкции для PowerShell — в [README агента](kmg-security-agent/README.md).

```bash
cd kmg-security-agent
cp .env.example .env
```

Укажите `LLM_BASE_URL`, `LLM_API_KEY` и `LLM_MODEL` в `.env` (без ключа работает режим `--mode static`); этот файл исключен из Git. Если локальный `.env` уже существует, сохраните его и пропустите копирование примера. Ключи между коллегами через репозиторий не передаются.

```bash
export PYTHONPATH=src
export PYTHONDONTWRITEBYTECODE=1
python3.14 -m unittest discover -s tests
python3.14 -m kmg_security_agent doctor
python3.14 -m kmg_security_agent scan --repo ../KMG-Digital-Hackathon --output reports/demo
```

Запуск сервера KMG для статического анализа не требуется. Установка и запуск самого приложения описаны в [его README](KMG-Digital-Hackathon/README.md).

## Текущее состояние

Первая консольная реализация создана. Локальные тесты проверяют чтение файлов, исключение секретов, валидацию ответов и цитат, полноту, таймауты и коды завершения. Живая Qwen верно классифицировала два синтетических примера по ИБ-01; дальнейший прогон прерван HTTP 429 от провайдера. Полный живой аудит и оценка всех 16 примеров пока не завершены.

- [Инструкция агента](kmg-security-agent/README.md)
- [Техническое задание](kmg-security-agent/docs/TECHNICAL_SPEC.md)
- [Архитектура](kmg-security-agent/docs/ARCHITECTURE.md)
- [Проверенные результаты и ограничения](kmg-security-agent/docs/VALIDATION.md)

Секреты, локальные отчеты, runtime, базы и кеши не публикуются. Каждый запуск создает свои отчеты локально; численные результаты прошлых проверок описаны в VALIDATION.md.

## Совместная разработка

Создавайте отдельные ветки для изменений и отправляйте pull request. Изменения проверяемого приложения относятся к `KMG-Digital-Hackathon/`, изменения анализа, промптов и тестов — к `kmg-security-agent/`. Перед pull request запускайте локальные тесты агента.

Обе папки — обычные каталоги одного Git-репозитория. Отчет сканирования привязывается к commit общего репозитория и хешу содержимого проверяемой подпапки.

## GitHub Actions

[Общий workflow](.github/workflows/security-check.yml) на каждый push запускает тесты на Ubuntu и Windows, затем отдельный шаг **ИБ-проверки** всего проекта и демонстрационный шаг выпуска, который разрешается только при коде `0`. Ключ модели — secret `LLM_API_KEY` (variables `LLM_BASE_URL`, `LLM_MODEL`); без него проверка выполняется детерминированными правилами. Ручной запуск позволяет указать другой проверяемый репозиторий и ветку. Отчёты сохраняются артефактом `security-report-*`.

Коды `scan`: **0** — нарушений нет; **1** — найдены нарушения, следующий шаг блокируется; **2** — проверка не выполнена. Для запрета merge отметьте шаг `ИБ-проверка (шаг CI/CD)` как required check.
