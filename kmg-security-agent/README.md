# KMG Security Agent

Консольный анализатор Python/Django-проектов по восьми требованиям ИБ хакатона KMG Digital. Он инвентаризирует исходники, конфигурацию и документы, отправляет отобранный и замаскированный контекст выбранной модели через OpenRouter, проверяет цитаты и формирует JSON/Markdown для CI.

Текущий статус: первая консольная реализация создана. Два живых тестовых примера пройдены; дальнейшая оценка остановлена HTTP 429. Полный анализ и точность восьми проверок еще не подтверждены. См. [проверенное состояние](docs/VALIDATION.md).

Агент не импортирует и не исполняет код цели, не запускает ее сервер и не исправляет исходники. Статический вывод модели не является сертификацией или динамическим испытанием Windows ACL. Производственные промпты не содержат заранее подготовленного списка ошибок тестового проекта.

Текущее проверенное состояние и незавершенные этапы: [VALIDATION.md](docs/VALIDATION.md).

## Быстрый запуск

Нужен Python **3.11 или новее**; разработка и CI используют **3.14**. Полный `scan` этой версии поддерживает **macOS/Linux**: безопасное чтение использует POSIX no-follow/openat API. На Windows инвентаризация завершается с ошибкой вместо небезопасного обхода ссылок; Windows-код цели можно статически анализировать на macOS/Linux. Сам агент использует только стандартную библиотеку. Устанавливать Django, зависимости проверяемого проекта, pytest или SDK модели не нужно.

Выполняйте команды из папки `kmg-security-agent` общего репозитория. Ключ предоставляется в переменной `OPENROUTER_API_KEY` либо в локальном `.env` **агента**, исключенном из Git. `OPENROUTER_MODEL` содержит точный ID модели; исходная настройка — `qwen/qwen3.8-27b:free`. Ключ не помещается в командную строку, документацию и артефакты.

```bash
export PYTHONPATH=src
export PYTHONDONTWRITEBYTECODE=1
python3.14 -m kmg_security_agent --help
python3.14 -m kmg_security_agent doctor --timeout 120
python3.14 -m kmg_security_agent scan \
  --repo ../KMG-Digital-Hackathon \
  --output reports/demo \
  --timeout 1560 --request-timeout 180 --max-requests 25
```

`doctor` делает небольшой реальный запрос без исходников и выводит модель, время и использование API. Успех означает доступность ответа в момент проверки, а не наличие квоты на весь проект. `scan` выполняет настоящий модельный анализ; достаточность 25 запросов зависит от размера проекта, повторов и скорости сервиса. При недостаточном бюджете результат будет незавершенным, а не успешным.

Если файл настроек расположен отдельно, глобальный параметр указывается **перед** командой:

```bash
python3.14 -m kmg_security_agent --env-file /path/to/agent-settings.env doctor
python3.14 -m kmg_security_agent --env-file /path/to/agent-settings.env scan \
  --repo ../KMG-Digital-Hackathon --output reports/demo
```

Переменные окружения имеют приоритет над `.env`. Без `--env-file` читается `.env` текущего каталога агента. Агент не ищет и не загружает `.env` проверяемого проекта. `OPENROUTER_BASE_URL` позволяет явно выбрать совместимый endpoint; по умолчанию используется `https://openrouter.ai/api/v1`. Автоматической смены модели нет. Для OpenRouter платная модель отклоняется, пока пользователь явно не задаст `ALLOW_PAID_MODEL=true`; эта настройка не нужна для исходной демки.

Перед внешней отправкой исходников должны быть согласованы выбранный сервис и режим обработки данных. Наличие API-ключа само по себе не означает такого согласования.

## Результат и коды завершения

`--output` — родительская папка. Каждый запуск создает в ней новый каталог с временем UTC и случайным суффиксом. Итоговая строка CLI показывает точный путь. Вывод внутри проверяемого дерева отклоняется.

В каталоге завершенного анализа находятся:

- `report.json` — машиночитаемый результат и восемь статусов требований;
- `report.md` — тот же результат для специалиста;
- `manifest.json` — состав проекта, причины исключений и покрытие;
- `run.log` — краткий результат и диагностические сведения.

Отчет привязан к фактическому SHA цели, если она является Git-репозиторием, и к хешу анализируемого содержимого. Незакоммиченные изменения отражаются отдельно. В finding указываются ИБ-ID, критичность, объяснение, исправление и проверенная цитата существующего участка. Для DOCX номера относятся к извлеченному тексту, а не к странице Word.

| Код | Значение для `scan` | CI |
|---|---|---|
| 0 | Обязательные проверки завершены; подтвержденных нарушений ИБ нет | Разрешить следующий шаг |
| 1 | Проверки завершены; найдено хотя бы одно нарушение ИБ-01…08 | Блокировать |
| 2 | Ошибка или незавершенное обязательное покрытие, даже если нарушения уже найдены | Блокировать |

Ошибка имеет приоритет над находками: `2 > 1 > 0`. Предупреждения и дополнительные дефекты спецификации сами по себе не дают код `1`. Число находок не является процентом полноты. Точная схема и неизменность цитаты проверяются программно; правильность семантического вывода остается ограничением LLM.

ТЗ организатора одновременно требует отчет независимо от результата, частичный отчет при timeout и завершение **без отчета** при ошибке внешнего сервиса. В демке принято специальное исключение:

- Общий timeout или внутренняя незавершенность: частичный `report.json/md`, код `2`.
- Фатальная ошибка внешнего API: `run-status.json/md`, manifest и лог, **без итогового отчета соответствия**. Уже собранные результаты помечаются незавершенными.
- Жесткое завершение runner/process может помешать сохранению файлов. Ошибка начальной конфигурации до создания каталога выводится в stderr с кодом `2`.

Эта трактовка подробно описана в [ТЗ демки](docs/TECHNICAL_SPEC.md). Документ ТЗ фиксирует исходный этап проектирования; выбранная реализация заменяет предложенные внешние библиотеки эквивалентами стандартной библиотеки и использует `unittest`.

## Проверочные инструкции и полнота

[Реестр требований](src/kmg_security_agent/resources/requirements.json), [системный промпт](src/kmg_security_agent/resources/system.md) и [восемь инструкций](src/kmg_security_agent/resources/skills) входят в исходники. Это skills анализатора по требованиям хакатона.

Агент собирает весь проект, а не только Git diff. Источники разбиваются на фрагменты, проходят пакетный обзор, затем сопоставляются по каждому требованию с учетом импортов, маршрутов, общей защиты и настроек. Все фрагменты должны получить подтверждение рассмотрения. Недостающий контекст и превышенный бюджет учитываются явно. Полноценная модель всех динамических вызовов Python не заявляется.

Рабочие секреты, `.env`, приватные ключи, базы, runtime, `.git`, виртуальные окружения и генерируемые артефакты исключаются без чтения содержимого. Ссылки наружу и неподдерживаемые объекты не обходятся молча. Значимые файлы проверяются на изменения за время анализа. Маскировка секретов применяется до внешней передачи и перед сохранением результатов; универсальное распознавание любых секретов не гарантируется.

Комментарии и документы цели не могут управлять агентом: найденные в них инструкции рассматриваются как недоверенные данные. Модель не получает инструмента исполнения команд.

## Тесты и отдельная оценка модели

Обычные тесты выполняются локально и в CI без сетевых запросов и API-ключа:

```bash
PYTHONPATH=src python3.14 -m unittest discover -s tests -v
```

[Размеченные fixtures](tests/fixtures/README.md) содержат **16** независимых минипроектов — безопасный и небезопасный пример для каждого ИБ-ID. В нескольких случаях защита расположена в другом файле. В одном исходнике есть попытка подменить инструкцию анализатора. Каждый пример оценивается **только по своему требованию**; безопасный пример не является полностью безопасной системой или официальным эталоном организатора. Разметка не отправляется модели.

Живая оценка запускается отдельно:

```bash
PYTHONPATH=src python3.14 -m kmg_security_agent evaluate \
  --fixtures tests/fixtures --output reports/evaluation \
  --timeout 1560 --request-timeout 180 --max-requests 40
```

Это **не менее 16 модельных запросов**, возможны дополнительные попытки и несколько минут ожидания. Оценка расходует отдельную квоту; она не запускается на каждом push. Результаты — `evaluation.json/md`, совпадения по примерам, precision/recall классификации минипроектов и использование API. Это метрики статусов примеров; корректность путей доказательств дополнительно влияет на число совпадений, а точность отдельных находок ими не измеряется. Для `evaluate` код `0` означает совпадение всех ожиданий, `1` — завершенную оценку с расхождениями, `2` — незавершенность. Эта оценка не заменяет проверку на скрытой разметке организатора.

## GitHub Actions в общем репозитории

Обе папки находятся в одном Git-репозитории. Активный [workflow](../.github/workflows/security-check.yml) расположен в корне; он тестирует агент и анализирует соседнюю папку `KMG-Digital-Hackathon` из того же commit. SHA отчета относится к общему репозиторию, хеш содержимого — к проверяемой подпапке.

Офлайн-тесты выполняются на push и pull request. ИИ-анализ запускается на push или вручную, когда в Actions secrets задан `OPENROUTER_API_KEY`. Без этого секрета анализ и разрешение выпуска пропускаются; зеленые офлайн-тесты не означают проверенную безопасность. Ключи локального `.env` не загружаются в GitHub автоматически.

Необязательные variables: `OPENROUTER_MODEL`, `OPENROUTER_BASE_URL`. Workflow блокирует следующий демонстрационный шаг при кодах 1/2; реального deploy нет. Правила merge настраиваются отдельно в branch protection. Подробности совместной работы — в [корневом README](../README.md).
